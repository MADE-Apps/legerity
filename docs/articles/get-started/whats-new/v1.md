# What's new in v1.0

Legerity v1.0 is a ground-up modernization of the framework. It brings the dependency stack current with Selenium 4, Appium 8, and .NET 10, introduces a fluent locator API for composing element queries, and fixes longstanding issues with parallel test execution.

This is a major release with breaking changes. If you're upgrading from v0.x, see the [migration guide](xref:migration-v0-to-v1) for step-by-step instructions.

## .NET 10.0 target

All Legerity packages now target .NET 10.0 exclusively. The .NET Standard 2.0 target has been removed. If your test projects target .NET Framework or older .NET Core versions, you'll need to upgrade your target framework before adopting v1.0.

## Appium 8.x and Selenium 4.x

The framework has been upgraded from Appium 4.4.5 to Appium 8.x, which brings Selenium 4.35 as a transitive dependency. This is the most significant change in v1.0 and affects every element type and driver reference in the framework.

Key changes:

- **`AppiumElement` replaces `AppiumWebElement`** as the base element type across all platform wrappers.
- **Platform-specific element types removed.** `WindowsElement`, `AndroidElement`, and `IOSElement` no longer exist. All platform wrappers use `AppiumElement`.
- **Generic driver types removed.** `WindowsDriver<WindowsElement>` becomes simply `WindowsDriver`.
- **`WebDriver` replaces `RemoteWebDriver`** and **`WebElement` replaces `RemoteWebElement`** throughout the API surface.
- **`FindElementByXPath()` and similar convenience methods removed.** Use `FindElement(By.XPath(...))` instead.

## Fluent selector chaining

A new fluent API for composing element locator queries, available as extension methods on `By`. This is the headline developer experience improvement in v1.0.

**Simple shortcuts** extend any `By` locator:

```csharp
// Find a button with specific text
page.FindElement(By.TagName("button").WithText("Accept"));

// Find an element matching multiple criteria
page.FindElement(By.ClassName("card").WithAttribute("data-id", "123"));

// Find children within matched elements
page.FindElements(By.Id("form").ThenFind(By.TagName("input")));
```

**Builder API** for complex multi-constraint queries:

```csharp
// Same-element constraints (intersection)
page.FindElement(By.TagName("input")
    .That(by => by.HasAttribute("type", "email").HasAttribute("required", "true")));

// Scoped child search (nesting)
page.FindElement(By.TagName("form")
    .ThenFind(by => by.TagName("input").HasAttribute("type", "radio")));
```

**Platform-specific extensions** integrate with each platform's native locator strategies:

- **Windows:** `.HasAutomationId()`, `.WithAutomationId()`, `.ThenFindByAutomationId()`
- **Android:** `.HasContentDescription()`, `.WithContentDescription()`
- **iOS:** `.HasLabel()`, `.HasValue()`, `.WithLabel()`, `.WithValue()`
- **Web:** `.HasInputType()`, `.ThenFindByInputType()`, `.ThenFindListItems()`, `.ThenFindOptions()`, `.ThenFindTableRows()`

For full documentation, see [Locators](xref:core-locators).

## Thread-safe parallel testing

The driver lifecycle has been reworked for safe parallel execution:

- **`AppManager.App`** now uses `AsyncLocal<WebDriver>` instead of a static field. Each test execution context gets its own driver reference.
- **`AppManager.StartedApps`** uses `ConcurrentDictionary` for thread-safe access.
- **`AppManager.StopApp()`** uses `TryRemove` for idempotent cleanup, preventing `ObjectDisposedException` when multiple threads attempt teardown.
- **Driver disposal** is now resilient. `StopApp()` and `StopApps()` catch exceptions during `Quit()` to handle partially initialized or already-disposed drivers gracefully.

## ByAll intersection fix

`ByAll.FindElements()` now uses `Equals()`-based element comparison instead of `Intersect()`. In Selenium 4.x, `WebElement.GetHashCode()` is not consistent with `Equals()`, which caused `Intersect()` to silently return empty results. This was a latent bug that broke all `ByAll` queries after the Selenium 4 upgrade.

## Removed packages

The following third-party control wrapper packages have been removed:

- **`Legerity.MADE`** - MADE.NET control wrappers (DropDownList, InputValidator)
- **`Legerity.Telerik.Uwp`** - Telerik UWP control wrappers (RadAutoCompleteBox, RadBulletGraph, RadBusyIndicator, RadNumericBox)
- **`Legerity.WCT`** - Windows Community Toolkit control wrappers (BladeView, Carousel, Expander, InAppNotification, RadialGauge)

If you depend on these wrappers, you can create equivalent custom element wrappers using the [element wrapper guide](xref:core-element-wrappers).

## Removed browser support

- **Opera** - dropped in Selenium 4.
- **Internet Explorer** - end-of-life.
- **Edge Chromium** (`WebAppDriverType.EdgeChromium`) - redundant, since `WebAppDriverType.Edge` is Chromium-based by default in Selenium 4.
